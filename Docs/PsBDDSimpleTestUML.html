One simple test, two UML views

A UML activity diagram and a UML sequence diagram of a typical PsBDD run: one fixture, one Markdown document and one Given / When / Then / And scenario, from the project file to the saved document.

The test being drawn

This is the Customer List example cut down to one scenario and one Markdown document. The step methods are the same as in the walkthrough.

CustomerLookup.Tests.dpr
begin
  TDUnitX.CheckCommandLine;
  TPsBDDRun.RunStart := rsOverwrite;
  Runner := TDUnitX.CreateRunner;
  Runner.AddLogger(TDUnitXConsoleLogger.Create(True));
  try
    Results := Runner.Execute;
  finally
    TPsBDDRun.PerformConversions;
  end;
  if not Results.AllPassed then
    ExitCode := 1;
end.
CustomerList.Feature.Tests.pas
procedure TCustomerListFeature.SetupFixture;
begin
  FFeatureWriter := TPsBDDFeatureDocumentWriter.Create;
  FFeatureWriter.Title := 'Customer list';
  FFeatureWriter.Description := CUSTOMER_DESCRIPTION;
  FFeatureWriter.Status := fsInDevelopment;
  FFeatureWriter.RequirementReference := 'REQ#014';
  FFeatureWriter.RequirementText := CUSTOMER_REQUIREMENT;
  FFeatureWriter.AddDocument(TPsBDDMarkdownDocument.Create(
    'C:\Docs\CustomerList.md', auTester, False));
  FFeatureWriter.Open;
  FFeatureWriter.WriteFeature;
  FFeatureWriter.WriteRequirement;
end;

procedure TCustomerListFeature.CustomerIsFoundInTheList;
var
  Scenario: IPsBDDScenario;
begin
  Scenario := TPsBDDScenario.Create(
    FFeatureWriter.BeginScenario('Customer is found in the list'));
  Scenario
    .Given(AListWithSmithAndJones, 'a customer list with "Smith" and "Jones"')
    .When(SearchForSmith, 'the clerk searches for "Smith"')
    .&Then(TheCustomerIsFound, 'the customer is found')
    .&And(ExactlyOneMatch, 'exactly one match is returned');
end;  // Scenario released here: status written

procedure TCustomerListFeature.TearDownFixture;
begin
  FFeatureWriter.Close;  // CustomerList.md saved here
  FFeatureWriter := nil;
end;

Activity diagram

The control flow of the whole run. Each column (partition) is the part of the code that does the action. The step loop in the middle runs once for each step in the chain: four times here.

Reading it

  • Rounded box: an action. Diamond: a decision (one flow in, guarded flows out) or a merge (flows in, one out).
  • Guards in square brackets say which way the flow goes.
  • Filled circle: start. Ringed circle: end.

In this run

  • rsOverwrite has already deleted the old file, so [no] is taken at "file exists?". With rsAppend the old file is loaded and the new feature is added to it.
  • Nothing reaches the disk until Close. Until then the document is held in memory.

When a step fails

  • The exception leaves the chain, so the remaining steps never run or appear in the document.
  • The status is still written when Scenario is released, as Failed with the first message. DUnitX then reports the failure.

Sequence diagram

The same run as messages between objects. Objects created during the run have their head at the point they are created. The loop frame for the steps shows the Given step. When, &Then and &And send the same messages with their own kind.

Reading it

  • Solid line, filled head: a call. Dashed line, open head: a return.
  • Narrow box on a lifeline: the object is running code.
  • X at the end of a lifeline: the object is freed.
  • loop, alt and opt frames: repeated, alternative and optional messages.

Worth noticing

  1. BeginDocument acts on the first open of a path in the run only. A second fixture writing to the same file appends to this one.
  2. A step line is written before its method runs, so a failing step is the last line in the document.
  3. Nothing calls the scenario to say the method has ended. The status is written from its destructor, when the reference count reaches 0 at end;.
  4. Save writes the file only when something was written to the document.

With HTML or a PDF too

  • Add an HTMLDocument and the feature writer and scenario writer send each Write… message to both documents.
  • Register a PDF with AddConversion and message 41 converts the saved Markdown. Here none is registered, so it does nothing.
